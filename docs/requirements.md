# 概要
アプリ名: MyTodo
シンプルなTodoアプリ

# 対象と制約
- 対象プラットフォーム: Windows, macOS
- 開発環境: フロントエンド TypeScript + React（Tauri）+Tailwind CSS、バックエンド Rust
- 公開方針: ソースは GitHub で公開（現時点ではソース公開のみを想定）
- ローカライゼーション: 日本語のみ（多言語対応は行わない）
- アクセシビリティ: 対応しない
- ユーザー: 開発者自身が主な利用者。一般公開はするが、一般ユーザー向けの追加対応は予定しない。
- 利用シーン: stickだとTodoとしては使いづらい。常駐アプリとして起動していつでも呼ばせるようにする。
- 責任範囲: 自身の普段使いで問題が出ない限りを前提とし、他環境での致命的な不具合には対応保証をしない。

## 用語
- タスク: Todoの1件のデータ。以降、Todoと同義で使用する。
- 未完了タスク: `is_done` が `false` のタスク。
- 完了タスク: `is_done` が `true` のタスク。
- アクティブ化: ホットキー、トレイ／メニューバーの「表示」、またはウィンドウのフォーカスによりUIを前面に表示すること。

# 機能要件
1. 表示と起動
	- ホットキーでUIを表示。デフォルトは macOS では `Cmd+Alt+Shift+Q`、Windows では `Ctrl+Alt+Shift+Q` とする。設定で変更可能とし、変更は次回起動後も維持する。
	- ホットキーはUIが非表示の場合は表示して前面化し、表示中の場合は前面化のみ行う。
	- 件数に上限は設けず画面に表示できない情報はスクロールで確認が可能
	- 完了したタスクは完了日時から72時間経過後に削除する。削除処理はアプリがアクティブ化したタイミングで行い、削除結果を直ちに保存する。
	- 一覧の情報はドラッグ＆ドロップで並べ替えが可能
	- タスク完了のチェックは一覧から変更できる。未完了を完了にすると完了済みタブへ、完了を未完了に戻すと未完了タブへ移動する。完了にする際は完了日時を設定し、未完了に戻す際は完了日時を消去する。
	- 未完了、完了は別タブで表示する
	- 並べ替えは各タブ内でのみ可能とする。並べ替え後は表示順を保存し、次回起動時に復元する。
	- 一覧にはTodoの内容を最大2行分表示し、収まらない場合は三点リーダーを表示する。
	- タスクをクリックすると編集画面を表示する。

2. 登録・編集
	- 追加ボタンのクリックで登録画面を表示する。入力項目は完了フラグ、重要度を表すリスト、Todoの内容、期限とする。OKボタンクリックで登録、キャンセルボタンクリックで変更を保存せず画面を閉じる。
	- Todoの内容は必須とし、空文字または空白文字のみでは登録・更新できない。入力上限は10,000文字とする。
	- 重要度は `低`、`中`、`高` の3段階とし、初期値は `中` とする。
	- 期限は任意の日付とし、未入力を許可する。期限切れでもタスクを自動完了・自動削除しない。
	- 編集は登録時と同じ画面で行い、OKボタンクリックで変更内容を上書きする。
	- 編集画面には削除操作を用意する。削除は確認後に実行し、取り消し機能は提供しない。
	- タスクトレイ／ランチャー常駐アイコンのコンテキストメニューには「表示」「終了」を用意する。

# 非機能要件
- パフォーマンス: ホットキー押下からUI表示までの目標は 1 秒以内（目標値）。表示済みの要素は逐次非同期読み込みで表示可。
- 常駐: ログイン時に起動する（タスクトレイ／メニューバーアイコンを使用）。
- 保存とバックアップ: Todoの情報は JSON 形式で保存。アプリと同じフォルダに `MyTodo.data` を保存する。設定も同一ファイルに保存する。更新操作ごとに保存し、保存失敗時は操作を失敗として扱い、画面にエラーを表示する。バックアップはアプリ起動時にデータファイルが存在する場合のみ作成し、最大3世代保持する。
- ロギング: 操作ログをアプリフォルダに出力。ログファイルは1MB超でローテートし、旧ファイルは5世代保持。
- テスト: 単体テスト・結合テストを実施（フロントとバックエンドの結合を含む）。

# データ・永続化
- 格納形式: JSON（スキーマは別途定義）
- 設定ファイル名/場所: アプリ同一フォルダに `<appname>.data`（JSON）を置く。
- 保存項目:
	- `id`: UUID v4形式の文字列。タスク作成時に生成し、以後変更しない。
	- `is_done`: 完了状態を表す真偽値。
	- `todo`: タスク本文。
	- `limit_date`: 期限。未設定の場合は `null`、設定する場合は `YYYY-MM-DD` 形式の文字列。
	- `importance`: `low`、`medium`、`high` のいずれか。
	- `completed_at`: 完了日時。未完了の場合は `null`、完了時はUTCのISO 8601形式文字列。
	- `created_at`: 作成日時。UTCのISO 8601形式文字列。
	- `updated_at`: 最終更新日時。UTCのISO 8601形式文字列。
	- `order`: タブ内の表示順を表す0以上の整数。
- 既存の `createedAt` は誤記のため `created_at` を正とする。永続化形式の詳細スキーマは `docs/data-schema.md` に定義する。

# IPC 契約概要
- フロントエンドとバックエンドは Tauri の IPC を通じて連携する。
- 主な処理は以下のカテゴリに分かれる。
  - Todo: `todos/list`, `todos/add`, `todos/update`, `todos/delete`, `todos/reorder`
  - ログ・バックアップ管理: `log/get-config`, `backup/get-status`
- 共通レスポンス形式は `success` / `data` / `error` を持つ構造とし、フロントは `success` を確認して処理する。
- 更新通知はイベントとして送信し、画面表示を状態同期する。
- `todos/list` は未完了・完了を指定して取得し、表示順に返す。`todos/add`、`todos/update`、`todos/delete`、`todos/reorder` は永続化完了後に成功を返す。
- 詳細は `docs/ipc-contract.md` に定義する。

# UI/UX 要件
- エラーメッセージはユーザに分かりやすく表示する（起動失敗時はダイアログ表示）。
- エラーメッセージは表示と同時にログ出力を行う。
- 想定するエラー状況:
	- データまたは設定ファイルの読み込み・解析に失敗した場合は、破損ファイルを上書きせず、起動失敗としてダイアログ表示とログ出力を行う。
	- データ、設定、ログ、バックアップの書き込みに失敗した場合は、操作を成功扱いにせず、画面にエラーを表示してログ出力する。
	- ホットキーの登録に失敗した場合は、起動を継続し、トレイ／メニューバーの「表示」から利用できることを画面に通知する。

---

# セキュリティ・権限
- 起動に失敗した場合は、ユーザーに「起動に失敗しました」と表示し、詳細はログに出力する。
- 必要なファイルアクセス権限や実行権限は OS の要件に従う。

# テスト・受け入れ基準
- アプリ起動後、トレイ／メニューバーアイコンが表示され、コンテキストメニューからUIの表示とアプリ終了ができる。
- macOSおよびWindowsで既定ホットキーを押下すると、1秒以内を目標にUIが前面に表示される。
- タスクを追加、編集、削除、完了、未完了へ戻す、並べ替える各操作ができ、アプリ再起動後もその結果が維持される。
- Todoの内容が空の場合は登録・更新できず、エラーメッセージが表示される。
- 完了日時から72時間を超えた完了タスクは、次回アクティブ化時に削除される。72時間以内の完了タスクは削除されない。
- タスクが3件以上ある場合でも未完了・完了タブを切り替えて確認でき、表示領域を超える場合はスクロールできる。
- データファイルが存在する状態で起動するとバックアップが作成され、世代数が3を超えない。
- 保存または読み込みに失敗した場合、ユーザーにエラーを表示し、操作ログに詳細が記録される。
- 単体テストでデータ操作、期限切れ完了タスクの削除、並べ替え、入力検証を確認する。結合テストでIPC経由の追加・更新・削除・再読み込みを確認する。
